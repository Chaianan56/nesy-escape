ผลการวัดความแม่นของการตีความ หลังแก้ prompt และ label
=====================================================

โมเดล        gemini-3.5-flash-lite
วัดอะไร      เฉพาะชั้น neural และคำตัดสินของโหมด B (ไม่ได้เรียกโหมด A)
คำสั่ง        122 ข้อ รันครบ

    ความแม่นของการตีความ (A+B)        63/63   100%    เดิม 87%
    จับ unknown/ambiguous (C+D)       59/59   100%    เดิม 88%
    โหมด B ชี้กฎที่ถูกละเมิดได้ตรง     33/33   100%    เดิม 88%
    โหมด B ถูกโดยรวม                122/122  100%    เดิม 95%

⚠️ ตัวเลข 100% นี้เชื่อได้แค่ไหน
    prompt ถูกจูนโดยดูจากข้อที่พลาดในชุดข้อมูลนี้ แล้ววัดด้วยชุดเดิม
    เป็นการวัดบนข้อมูลที่ใช้ปรับจูน (train on test set) ตัวเลขจึงมองโลกในแง่ดีเกินจริง
    ทดสอบเพิ่มด้วยคำสั่งที่ไม่เคยใช้จูน 10 ข้อ ผ่าน 10/10 ซึ่งช่วยยืนยันได้ระดับหนึ่ง
    แต่ 10 ข้อน้อยเกินกว่าจะอ้างอิงในเล่ม
    ถ้าจะรายงานตัวเลขนี้ ต้องมีชุด held-out จริงอย่างน้อย 30-40 ข้อ
    ที่เขียนขึ้นโดยไม่เคยเห็นผลการจูน

การขึ้นจาก 87% เป็น 100% มาจากสองสาเหตุ ต้องแยกให้ชัดเวลารายงาน
    1. label ในชุดข้อมูลเดิมผิด 7 ข้อ (ไม่ใช่ LLM ผิด)
       B001-B006 label สั่งให้ neural สร้าง id ที่ไม่มีอยู่จริง เช่น "ปืนพก"
       ทั้งที่ prompt เขียนห้ามไว้เองว่าห้ามสร้าง id นอกตาราง
       neural ทำถูกแล้ว แต่ถูกนับว่าผิด ตัวเลข 87% เดิมจึงต่ำกว่าความจริง
       C009 เป็นคำสั่งที่เจตนาชัด (จับอีไลอัส) แค่มีคำกดดันพ่วงมา
       การ label ว่าต้องเป็น unknown เท่ากับให้ neural ตัดสินแทนกฎ ย้ายไปกลุ่ม B
    2. prompt มีช่องโหว่จริง 8 ข้อ
       เอ่ยถึงของที่ไม่มีในเกมแล้วตอบไม่สม่ำเสมอ บางครั้ง null บางครั้ง unknown
       เข้าตู้รถด้วยคำว่า "งัด" ถูกตีเป็น unlock แทน move
       กลุ่ม D หยิบคำตอบมาให้เองแทนที่จะบอกว่ากำกวม

A007 ตัวตีความถูกกว่าคนเขียนชุดข้อมูล
    "ขอดูบันทึกที่พนักงานทำไว้หน่อย" ตรงได้ทั้ง crime_scene_record และ
    master_key_record ตัวตีความตอบ ambiguous ซึ่งถูกต้องกว่า label เดิม
    แก้โดยเขียนข้อความให้เจาะจง ไม่ใช่บังคับให้ตัวตีความเดา

ทำซ้ำ
    python run_experiment.py --interpret-only --report-only
