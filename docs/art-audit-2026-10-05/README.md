## จุดที่ยืนยันได้และควรแก้ก่อน

### 1. ช่วงเปลี่ยนตู้ ภาพเก่ายังอยู่แต่ข้อความเป็นตู้ใหม่

พบขณะย้ายจากห้องเกิดเหตุไปตู้ระบบไฟ: ตำแหน่งกับคำตอบเปลี่ยนก่อนภาพใหม่โหลดเสร็จ จึงดูเหมือนใช้ภาพผิดฉากชั่วคราว เมื่อโหลดเสร็จภาพถูกต้อง

`frontend/art.js` เปลี่ยน src โดยไม่ซ่อน/ลดความเด่นภาพเก่า; `frontend/art.css` วาง art-status ที่ขอบล่าง ขณะที่ dialogue-panel ใน `frontend/cinematic.css` อยู่ตำแหน่งเดียวกันและมี z-index 2 จึงบังข้อความโหลดบางส่วน

ข้อเสนอ: แสดงสถานะโหลดเหนือกล่องบทสนทนาและแยกภาพที่กำลังโหลดจากภาพที่พร้อมแสดง ไม่ควรให้ภาพเก่าสื่อว่าเป็นห้องปัจจุบัน

### 2. ไฟล์ภาพใหญ่ เพิ่มเวลารอภาพใหม่

28 PNG รวม 51,614,373 bytes (~49.2 MiB), ภาพละ 1,565,795–2,071,764 bytes ไม่มีข้อสรุปว่าโหลดทั้งหมดพร้อมกัน แต่แต่ละภาพที่ยังไม่ cache มี payload ขนาดนี้

ข้อเสนอ: ทำ WebP/AVIF คุณภาพเหมาะสมและ thumbnail สำหรับสมุดคดี ตรวจความอ่านได้ของนาฬิกา/เอกสารหลังบีบอัด แยกการวัดเวลาโหลดรูปจากเวลา Neural

### 3. รายการสิ่งของยังเป็นของตู้ก่อนหน้าระหว่างโหลดสมุดคดี

พบชั่วคราวหลังเปลี่ยนตู้: ตำแหน่งและข้อความใหม่แล้ว แต่รายการใต้ภาพยังเป็นของตู้เก่า `PixelUI.refresh()` อัปเดตภาพ/แผนที่ทันทีแล้วค่อยเรียก `/journal` หากคำขอล้มเหลว catch เปลี่ยนเฉพาะ journalStatus จึงมีโอกาสค้างรายการเก่าต่อไป (กรณีล้มเหลวเป็นผลจากตรวจโค้ด ไม่ได้ตัดเน็ตบนเว็บจริง)

ข้อเสนอ: ล้างรายการหรือระบุว่ากำลังโหลดทันทีเมื่อย้ายตู้ และผูกข้อมูลกับตำแหน่ง/รอบคำขอ

### 4. กล่องคำตอบบังรายละเอียดสำคัญของภาพ

ภาพ `live-final.png` แสดงกล่องคำตอบพาดทับร่างผู้ตายและพื้นห้อง ซึ่งเป็นพื้นที่หลักฐาน ข้อความห้องยาวต้องเลื่อนภายในกล่อง และรายการหลักฐานด้านล่างต้องเลื่อนแนวนอนอีกชั้น เป็นปัญหาความสะดวกในการเล่น แม้ภาพห้องถูกต้อง

ข้อเสนอ: มีกล่องคำตอบแบบย่อ/ขยายหรือย้ายข้อความยาวออกจากภาพ ให้เห็นฉากเต็มได้โดยยังเปิดอ่านคำตอบได้ง่าย

### 5. รูปโหลดล้มเหลวแล้วทำคำสั่งเดิมไม่ลองโหลดใหม่

ยืนยันด้วย VM ที่เรียก `frontend/art.js` จริงและ DOM stub: เรียก onerror แล้ว sync ภาพเดิม จำนวนการกำหนด src เพิ่ม 0 ครั้ง เพราะ `shown` ถูกตั้งก่อนภาพโหลด และเงื่อนไข `shown===view.asset` return ทันที

ข้อเสนอ: เก็บสถานะโหลดสำเร็จแยกจากภาพที่ร้องขอ และให้ลองโหลดซ้ำได้เมื่อ error

## จุดรองและความเสี่ยงจากโค้ด

- **alt ไม่อัปเดตเมื่อใช้ไฟล์เดียวกัน:** ตรวจพยานที่ตู้เสบียง caption เปลี่ยนเป็นภาพหลักฐาน แต่ alt ยังเป็นภาพฉาก ยืนยันด้วย VM; ย้ายการตั้ง alt ก่อน early return
- **คำสั่งหลายขั้นอาจข้ามบทสนทนา:** `runSteps()` ใน chat.js รอ API แต่ไม่รอผู้เล่นอ่าน NovelUI; ผลขั้นถัดไปเรียก onResult ใหม่ บทสนทนาขั้นก่อนจึงอาจหายจากฉากก่อนอ่านจบ ควรเพิ่ม integration test; ยังไม่ได้บังคับให้ Neural สร้างลำดับนี้บนเซสชันจริง
- **ข้อความ error อาจอยู่ใต้คำตอบเก่า:** history.js คงคำตอบที่มี card-header-bar ล่าสุด ขณะที่ cinematic.js เลื่อน feed กลับบนสุดเมื่อเพิ่มข้อความ หาก error ไม่มี header และคำตอบเก่ายาว อาจต้องเลื่อนถึงจะเห็น เป็นข้อพบจากโค้ด ยังไม่ได้จำลอง provider failure บนเว็บจริง
- **ชื่อสำหรับ screen reader:** แผนผังตู้เสบียงอ่านว่า `ตู้ตู้เสบียง` จากการเติมคำว่าตู้ซ้ำใน pixel.js
- **เอกสารเก่า:** docs/stylized-art-integration.md ยังบอกว่าเข้าชั้นหนึ่งแล้วแสดง corridor ซึ่งไม่ตรง aad054d แล้ว
- **ภาพหลักฐานใช้ร่วมกัน:** detail-gideon รวม 4 รายการและ detail-vincent รวม 2 รายการ ภาพอาจให้เห็นร่องรอยอื่นก่อนกดตรวจ เป็นเรื่องการออกแบบปริศนา ไม่ใช่ mapping ขาด

- เข้าตู้ 4 และดูรอบๆ ใช้ scene-04-crime เหมือนกันแล้ว ไม่ใช่ corridor
- ภาพห้องแพทย์ใช้กับลิโอรา/เวชระเบียนภายใน first_class_car เดียวกัน ตำแหน่งใหญ่ยังเป็นตู้ 4 ตามเนื้อเรื่อง
- เข้าหัวรถจักรถูกปฏิเสธและใช้ภาพทางเข้า พร้อมระบุว่ายังอยู่ตู้เดิม ไม่ใช่แอบย้ายตำแหน่ง
- **ตราขี้ผึ้งและแหวนเป็นข้าวหลามตัดในวงกลม ตรงกับ story.json ปัจจุบัน** ข้อสงสัยเรื่องนก/กุญแจจากคำบรรยายอื่นไม่ใช่ข้อบกพร่องของเวอร์ชันนี้
- เวลานาฬิกาพก 20:25, นาฬิกาผนัง 21:15 และบันทึกระบบไฟ 21:14/21:15/21:18 สอดคล้องข้อมูลเกมในการตรวจภาพ
- ทุก object มีภาพสมุดคดี และ ending ทั้ง 6 ชี้ไปไฟล์ที่มีจริง ไม่พบ mapping หาย
- take/use/unlock/burn ไม่รองรับวัตถุในฉากปัจจุบันตาม engine/tests จึงไม่รายงานว่าการไม่เปลี่ยนภาพของ action เหล่านี้เป็นบั๊กที่ผู้เล่นเข้าถึงได้

## ลำดับแนะนำ

1. แก้ช่วงเปลี่ยนภาพและรายการสิ่งของให้สอดคล้องกัน พร้อม retry ภาพ
2. ลดน้ำหนักภาพและทำให้กล่องข้อความย่อได้
3. ทดสอบคำสั่งหลายขั้น บทสนทนา และ error ใน UI ร่วมกัน
4. เก็บ alt/ข้อความซ้ำ/เอกสารเก่า แล้วตรวจ integration หลังรวม main อีกครั้ง

การตรวจนี้ไม่รับรองทุกประโยคภาษาธรรมชาติ ทุกอุปกรณ์ หรือความพร้อมของบริการ AI ตลอดเวลา ทดสอบ responsive เบื้องต้นไม่พบ body ล้นแนวนอนที่ขนาดแคบ แต่ยังไม่ใช่การทดสอบมือถือจริงพร้อมแป้นพิมพ์และ touch
