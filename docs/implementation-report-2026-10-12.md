# Nocturne Express — รายงานนำเรื่องใหม่เข้าเกม

เริ่มจัดทำ 12 ตุลาคม 2026 · ตรวจส่งมอบ 13 ตุลาคม 2026

งานรอบนี้นำข้อเท็จจริง A2 และเป้าหมายความซับซ้อนของคดีเข้าไฟล์เกม กฎ บทสนทนา หน้าเว็บ และเครื่องมือทดลองแล้ว การส่งมอบนี้เป็นต้นแบบที่ตรวจพฤติกรรมด้วยโค้ดได้ ยังไม่ใช่ผลวิจัยหรือรายงานความสนุกจากผู้เล่นจริง

## ขอบเขตการเปรียบเทียบที่ส่งมอบ

หน้าเว็บเป็นเกม NeSy การเปรียบเทียบ neural-only รอบนี้ทำผ่าน `scripts/evaluate_modes.py` ที่รับสถานะและ `ParsedCommand` เหมือนกัน จึงควบคุมการตีความภาษาออกจากการทดลอง

ในโหมด neural โมเดลเป็นผู้ตัดสินผล บท หลักฐาน การมองเห็น ข้อสรุป และฉากจบเอง ไม่มี symbolic ตรวจแก้คำตอบหรือคืนสถานะให้ถูกระหว่าง rollout การตรวจรูปแบบ JSON ทำหน้าที่ตรวจชนิดข้อมูลเท่านั้น คำอธิบายโมเดลบันทึกว่าเป็นคำกล่าวอ้าง ไม่เรียกว่า trace จากกฎที่รันจริง

ผลของ CLI นี้ไม่ควรเรียกว่าเปรียบเทียบหน้าเว็บสองระบบครบวงจร หรือผลความเข้าใจผู้เล่น ชุดที่ใช้ระหว่างพัฒนาเป็น development corpus ต้องแยก held-out และทดสอบผู้เล่นก่อนสรุปผลวิจัย ดู [protocol](research-protocol-2026-10-12.md)

## การตรวจส่งมอบ

ผลตรวจล่าสุดวันที่ 13 ตุลาคม 2026:

- Python offline: **237 ผ่าน** โดยข้าม 5 ข้อที่เรียก LLM; มีเพียงคำเตือนเลิกใช้ API จาก dependency สองรายการ รวมเงื่อนไขฉากและ API ใหม่40ข้อ
- Frontend Node: **37 ผ่าน** ครอบคลุมการส่งคำสั่งซ้อน ประวัติ บทพูด เวลา และภาพประกอบ รวมการพักคำสั่งพ่วงขณะอ่านฉากและยกเลิกเมื่อคดีปิด
- ชุดอ้างอิงตัวตัดสิน revision 2: **58/58 ตาผ่าน** บน symbolic (38 กรณีแยก + rollout 20 ตา) ไม่มีการเรียก provider
- Browser: ตรวจคำสั่ง 40 ครั้งผ่านหน้าเว็บจริงจนถึง `true_ending` ตรวจประตูและบทที่ยังไม่เปิด รับกุญแจผ่านบทสนทนา เปิดหน้าต่างข้อสรุปจากข้อความโดยยังไม่บันทึกคำตอบ เลือกข้อสรุปผิดแล้วแก้ใหม่ โหลดหน้าเพื่อเล่นต่อ และยื่น 19 ชิ้นโดยตัดหลักฐานเสริมจากข้อสรุปก่อนหน้าได้ ไม่พบ JavaScript page error
- ฉากใหม่: บทนำ5หน้าอ่านก่อนนับเวลา ฉากทักท้วง4หน้าเปิดหลังพิสูจน์โดยไม่เพิ่มหลักฐาน และฉากย้อนหลัง6หน้าเปิดโดยสมัครใจหลังจบแท้ตามคู่หลักฐานที่ยื่น ตรวจทั้งสามคู่ผ่าน API; browserเล่นคู่กระดุมกับตรา
- ตรวจหน้าจอขนาด 1440×1000 และ 390×844; มีปุ่มเริ่มคดีสำหรับจอสัมผัส หน้าต่างหลักฐานเลื่อนอ่านได้โดยยังเห็นข้อสรุปและปุ่มส่ง

รันทวนได้ตาม README และ `scripts/check_story_browser.cjs` ภาพ/ผล browser อยู่ใน `tmp/browser-story-check/` ส่วนผลตัวตัดสินล่าสุดอยู่ใน `logs/research/symbolic-scenes-2026-10-13.json` ทั้งสองเป็นผลตรวจในเครื่อง ไม่ใช่ผลการทดลองจากผู้เล่นจริง รายละเอียดฉากอยู่ใน [ฉากเพิ่มเติม](new-scenes-2026-10-13.md)

เกณฑ์ตรวจของรอบนี้ประกอบด้วยเส้นทางเริ่มเกมจนจบทั้งสามคู่ การปิดกั้นวัตถุ/บทที่ยังไม่เปิด การเสนอข้อสรุปและแนบหลักฐาน การไม่เปิดเผยข้ออนุมานผ่านสมุดก่อนเวลา การหักล้างข้อกล่าวหาจากข้อมูลที่รู้แล้ว ฉากจบและหมดเวลา รวมเส้นทาง API และตัวตัดสิน neural แบบ stub โดยไม่เรียกบริการจริง

ยังไม่มีการเก็บผลโมเดลจริง ไม่มีผลทดลองผู้เล่น และไม่มีข้อสรุปว่าระบบใดเหนือกว่า ผลทดสอบอัตโนมัติยืนยันพฤติกรรมตามข้อกำหนดที่ตรวจ ไม่ยืนยันความเหมาะสมของภาระยื่น19–20หลักฐานหรือจังหวะเฉลยสำหรับผู้เล่นใหม่

## งานที่ต้องใช้ข้อมูลภายนอกก่อนสรุป

1. ทดลองผู้เล่นที่ยังไม่รู้เฉลย ตรวจจุดติดขัด ความเข้าใจสองเวลา และภาระเลือกหลักฐาน แล้วปรับจังหวะตามผล
2. สร้างและตรวจ held-out corpus แยกจากชุดพัฒนา ตรึงข้อมูล กฎ prompt และรุ่นโมเดลก่อนเก็บผลหลัก
3. รันบริการโมเดลที่เลือกเพื่อวัดผลจริง พร้อมรายงานเวลา token usage และข้อผิดพลาดจากบริการ
4. หากต้องการเทียบผู้เล่นผ่านหน้าเว็บทั้งสองแบบ ต้องนำตัวตัดสิน neural เข้าเส้นทางเว็บครบทุกจุดและตรวจความเท่าเทียมของข้อมูลก่อนเริ่มทดลอง

เอกสารแผนเก่ายังคงอยู่เป็นประวัติการตัดสินใจ ส่วนข้อความที่บอกว่าเกมยังไม่ได้แก้ให้อ่านตามวันที่ของเอกสารและสถานะล่าสุดใน [แผนดำเนินงาน](implementation-plan-2026-10-09.md)
