# แผนปิดช่องว่างเนื้อเรื่องและพัฒนา Nocturne Express

วันที่ 9 ตุลาคม 2026

สถานะล่าสุด 13 ตุลาคม 2026: นำ A2 เข้าเรื่อง กฎ บทตามสถานะ ด่านล็อก สมุดคดี และหน้าเว็บแล้ว พร้อม [ระยะ B](phase-b-design-2026-10-12.md), [walkthrough](walkthrough-new-story-2026-10-12.md) และเครื่องมือเปรียบเทียบตัวตัดสินที่รับคำสั่งซึ่งตีความแล้ว อ่านขอบเขตและผลตรวจล่าสุดใน [รายงานนำเข้าเกม](implementation-report-2026-10-12.md) ยังไม่มีผลบริการโมเดลจริงหรือผู้เล่นจริง และยังไม่ commit/push งานรอบนี้

เป้าหมายที่ผู้ใช้ชี้แจงเพิ่มเติม: สร้างคดีที่มีความซับซ้อนด้านเหตุผลเพียงพอสำหรับเปรียบเทียบ NeSy กับ neural-only ที่ไม่มีตัวตัดสิน symbolic พร้อมทำให้ผู้เล่นค่อย ๆ เข้าใจเนื้อเรื่องผ่านการเล่น เกณฑ์ที่ต้องใช้ในระยะ B อยู่ใน [ความซับซ้อนของคดี ความเข้าใจผู้เล่น และการเปรียบเทียบระบบ](design-goals-and-evaluation-2026-10-09.md)

- เพดานยื่นหลักฐานปัจจุบันคือ 15 ชิ้น ต้องตรวจใหม่หลังออกแบบเส้นทางใหม่ครบ

## 2. ทิศทางที่เสนอให้ใช้เป็นฐาน

1. ตัดปมผู้โดยสารคนที่แปดและประวัติอาเดรียน ใช้ชื่อหลัก **Nocturne Express** ระหว่างพัฒนา
2. คดีปี 1923 เป็นเรื่องกิเดียนใช้อำนาจเร่งเดินรถทั้งที่มีคำเตือน แล้วปกปิดคำสั่งและคำให้การหลังเกิดเหตุชน
3. เอเลียสรอดจากเหตุการณ์ ให้การขัดรายงาน ถูกทำให้ไม่น่าเชื่อถือ และเสียชีวิตภายหลัง ลิโอราต้องการคืนความน่าเชื่อถือให้บิดา
4. แคสเซียนเคยยอมปิดคดี และกำลังส่งหลักฐานเพื่อแก้ความผิด แฟ้ม C ต้องมีข้อมูลที่เชื่อมกิเดียนกับการปกปิดอย่างตรวจสอบได้
5. กิเดียนฆ่าแคสเซียนก่อนนรินทร์ขึ้นรถ หลอกเรื่องเลื่อนนัดเพื่อถ่วงเวลาพบศพ และฉวยใช้เหตุไฟดับของวินเซนต์ภายหลัง โดยไม่รู้แผนไฟดับล่วงหน้า
6. วินเซนต์มีเป้าหมายขโมยเอกสารของตนเอง ต้องมีคำตอบเรื่องผู้จ้างและเหตุผลที่ต้องขโมย แต่ไม่เปิดคดีหรือผู้ต้องสงสัยชุดใหม่
7. รักษาห้องหลักและตัวละครหลักเดิม เพิ่มพนักงานเป็นพยานที่คุยได้แต่กล่าวหาไม่ได้
8. ทำปมสองเวลาและคำโกหกให้เล่นได้ก่อนเพิ่มด่านล็อก ใช้ทางเชื่อมตัวบุคคล 2 ใน 3 ทางเป็นเป้าหมายการออกแบบ โดยทุกทางต้องมีน้ำหนักสมเหตุสมผล

รายละเอียดข้อเท็จจริงอยู่ในระยะ A ฉบับที่ 2 ส่วนเงื่อนไขที่นำเข้าเกมและวิธีเล่นจริงอยู่ในระยะ B กับ walkthrough ที่ลิงก์ด้านบน

## 3. ลำดับงาน

| ขั้น | งาน | สิ่งที่จะส่งให้ตรวจ | เกณฑ์จบขั้น |

**ความคืบหน้า 13 ตุลาคม:** ขั้น1–4นำเข้าโค้ดและเอกสารแล้ว ด่านทั้งสามในขั้น5ทำงานตามสถานะและมีเส้นทางตรวจแบบอัตโนมัติ ขั้น6มีการตรวจระบบและเครื่องมือเก็บผล แต่การลองกับผู้เล่นใหม่ การปรับจังหวะจากผลจริง และการตรึง held-out สำหรับผลวิจัยยังต้องดำเนินการ จึงไม่ถือว่าผ่านเกณฑ์ผู้เล่นของขั้น5–6แล้วจาก tests เพียงอย่างเดียว

## 5. แผนหลักฐานและระบบที่ต้องตกลงให้ครบก่อนลงโค้ด

### หลักฐาน

ทุกชิ้นต้องระบุว่าอยู่ที่ไหน ได้มาอย่างไร ผู้เล่นเห็นข้อความอะไร และรองรับข้อสรุปใด โดยแยก:

- ข้อเท็จจริงที่สังเกตได้ เช่น เวลาบนนาฬิกาหรือคำที่พยานพูด
- ข้อสรุปที่ต้องประกอบหลายแหล่ง เช่น เหตุรุนแรงเกิดก่อนไฟดับ
- ข้อสงสัยที่ยังไม่ใช่ข้อพิสูจน์ เช่น ไม่มีพยานที่อยู่ หรือมีกลิ่นยาอมตรงกัน

ออกแบบสายชา/กระดุม/ตราประทับให้เชื่อมบุคคลกับการมาพบหรือการจัดการเอกสาร แล้วใช้หลักฐานเวลาและเหตุการณ์ประกอบการกล่าวหา ไม่ยกระดับการมาพบให้เท่ากับเป็นฆาตกรอัตโนมัติ

ต้องตรวจทางเลือกชา+กระดุม, ชา+ตรา และกระดุม+ตรา ทั้งเงื่อนไขฉากจบ ข้อสรุป C02 สี่เสา และข้อความปิดคดี จัดชุดหลักฐานขั้นต่ำของทุกทางใหม่ก่อนตัดสินเพดานการยื่น

### บทสนทนาและพยาน

- รองรับบุคคลที่คุยได้และตรวจสอบคำให้การได้ โดยกล่าวหาไม่ได้ทั้งผ่าน UI และการพิมพ์คำสั่งตรง การระบุพยานเป็นเป้าหมายที่กล่าวหาไม่ได้ต้องไม่กินโอกาสกล่าวหา
- เริ่มจากบทเขียนล่วงหน้า 2–3 สถานะตามหลักฐาน ไม่สร้างระบบสนทนาทั่วไป
- ให้การเลือกบท การมอบหลักฐาน และบันทึกบทสนทนาใช้ผลการเลือกเดียวกัน ไม่แจกหลักฐานของบทถัดไปล่วงหน้า
- กลับมาถามหลังพบข้อมูลใหม่ได้ ถามซ้ำไม่เพิ่มของหรือหลักฐานผิดกติกา
- คำถามที่สมเหตุสมผลแต่เกินความสามารถของฉาก เช่น ขอผลตรวจอาวุธที่ยังไม่ได้ตรวจ ต้องได้รับคำตอบอธิบายขอบเขต ไม่หลุดเป็นข้อความไม่เข้าใจทั่วไป

### ความสอดคล้องระหว่างการกล่าวหากับฉากจบ

- สี่เสาสำหรับกิเดียนต้องตรงกับเงื่อนไข True Ending หลังเปลี่ยนกฎ
- ฉากจบกล่าวถึงเฉพาะหลักฐานและทางพิสูจน์ที่ใช้จริง
- หลักฐานล้างมลทินที่รู้แล้วต้องไม่ถูกหลบด้วยการไม่เลือกส่งชิ้นนั้น
- แยกคำติชมกรณียังไม่มีข้อมูล มีข้อมูลแต่ไม่ได้แนบ และมีข้อมูลขัดกับข้อกล่าวหา โดยไม่แจกเฉลยว่าต้องเลือกชิ้นไหน
- อธิบายให้ชัดว่าการส่งคดีที่เข้าเงื่อนไขฉากจบอาจจบทันที ส่วนการยื่นที่กฎไม่ยอมรับมีระบบโอกาสแก้ตัวตามเดิม

## 6. ไฟล์และจุดเชื่อมที่ต้องแก้ในภายหลัง

| กลุ่ม | ขอบเขต |
|---|---|
| เอกสารออกแบบ | สร้าง fact sheet A2 และสเปกระยะ B ระบุเอกสารเก่าว่าเป็นประวัติการออกแบบ เก็บต้นฉบับไว้ |
| เรื่องและกฎ | `data/story.json`, `data/rules.json`, `data/documents/` และ walkthrough |
| ตัวละครและสถานะ | `app/schemas.py` เท่าที่จำเป็น, `app/symbolic/engine.py`, validator, การส่งสถานะ/บันทึกหลักฐาน |
| คำสั่ง | prompt และตัวแปลคำสั่ง รองรับพนักงาน บทใหม่ และภายหลังรองรับรหัส/กุญแจ ตรวจเส้นทางคำสั่งต่อเนื่องด้วย |
| หน้าจอและข้อความ | `frontend/index.html`, สมุดคดี `CASE_BACKGROUND` ใน `app/main.py`, คำใบ้ รายการบุคคล หน้ากล่าวหา และภาพ/ข้อความฉากจบที่สัมพันธ์กัน |
| การทดสอบ | unit/integration ของ engine, API, คำสั่ง, validator และ frontend tests ที่เกี่ยวข้อง |

ไม่ลบ ID `secret_file` เพียงเพราะตัดคนที่แปด ให้เปลี่ยนเนื้อหาโดยรักษาหน้าที่ของเอกสารก่อน เพราะข้อสงสัยลิโอราและฉากจบผิดยังอ้างอิงอยู่

การตรวจคำว่า “ผู้โดยสารคนที่แปด / The Eighth Passenger” ต้องครอบคลุมข้อความที่ผู้เล่นเห็นจริงทั้งบทนำ หน้าเริ่ม สมุดคดี และเอกสารที่โหลด ข้อความในภาพตัวอย่างหรือบันทึกเก่าให้จัดสถานะเป็นประวัติ ไม่ไล่แก้สิ่งที่ไม่ใช่ส่วนเกมปัจจุบันโดยไม่จำเป็น

## 7. เพิ่ม Escape Room หลังแกนคดีผ่านการลองเล่น

1. เริ่มจากกระเป๋าสำนวนรหัส 1923 พร้อมคำใบ้สามระดับ รหัสถูกควรผ่านแม้ผู้เล่นเดาหรือจำได้ หากไม่มีข้อจำกัดในโลกเรื่องที่ระบุไว้
2. ทำผลของ `USE`/`UNLOCK` ให้สอดคล้อง รองรับกุญแจจริง การหยิบ และรายการของติดตัว รักษาการตรวจที่ไม่ปลดล็อกไว้
3. เพิ่มห้องแพทย์และห้องไฟทีละด่าน ระบุว่าแต่ละห้องเป็นทางจำเป็น ทางเลือก หรือทางเสริมตามแผนหลักฐาน
4. แยกของที่ถูกปิดกั้นทางกายภาพออกจากรายละเอียดที่ผู้เล่นเพิ่งรู้ว่าจะตรวจเทียบ ตรวจทุกช่องทางไม่ให้เฉลยหลุดจากชื่อวัตถุ/บทพูด/เมนู/สมุดคดี
5. ตรวจกราฟกุญแจและเงื่อนไขจากสถานะเริ่มต้น ห้ามมีของจำเป็นอยู่หลังด่านที่ต้องใช้ของชิ้นนั้นเอง

แต่ละด่านต้องรวมข้อมูล กฎ ผลเปลี่ยนสถานะ ตัวแปล UI และการทดสอบที่เกี่ยวข้องให้ครบก่อนขยายด่านถัดไป

## 8. การยืนยันผลและการแบ่งงาน

### ก่อนเริ่มแก้โค้ด

รันชุดทดสอบเดิมที่ไม่ต้องเรียกบริการภายนอกเพื่อเก็บฐาน แยกความล้มเหลวที่มีอยู่ก่อนออกจากผลของงานใหม่ ไม่เรียกการทดสอบที่เสียโควตาโดยไม่จำเป็น

### เงื่อนไขผ่านที่ต้องมี

- เดินเรื่องและส่งคดีสำเร็จได้จากสถานะเริ่มต้นด้วยข้อมูลที่ผู้เล่นเข้าถึงจริง
- ทั้งสามคู่ของทางเลือก 2 ใน 3 ใช้ได้จริง ไม่มีคู่ใดติดเพดานหลักฐาน
- ข้อมูลไม่ครบไม่เกิดข้อสรุปแรงเกินหลักฐาน; ข้อมูลครบต้องไม่ถูกปฏิเสธ
- พยานกล่าวหาไม่ได้ บทพูดและหลักฐานตรงกัน และกลับมาถามใหม่ได้ตามเงื่อนไข
- หลักฐานซ่อนไม่หลุดผ่านการพิมพ์ชื่อ/ID ตรงหรือช่องทางข้อมูลอื่น
- ทดสอบฉากจบแท้ คดีไม่ครบ กล่าวหาผิด จำนวนโอกาสแก้ตัว และหมดเวลา
- ตรวจหน้าเว็บจริงว่าชื่อเรื่อง เป้าหมาย สมุดคดี และภาพฉากจบตรงกับผลระบบ
- ทดลองผู้เล่นใหม่รอบนำร่อง วัดเวลาเล่นแยกเวลารอระบบ การใช้คำใบ้ และความเข้าใจปมสองเวลา จำนวนผู้เล่นเล็กใช้หาปัญหา ไม่อ้างเป็นผลยืนยันทางสถิติ

### การแบ่งชุดเปลี่ยนแปลงเมื่อเริ่มทำจริง

1. เอกสาร A2/B และกราฟหลักฐาน
2. ความสามารถพยาน/บทสนทนาที่เข้ากับข้อมูลเดิมได้ พร้อมทดสอบ
3. ย้ายเนื้อเรื่องและกฎสู่เวอร์ชันใหม่พร้อมกัน รวมข้อความผู้เล่นทุกจุดและ walkthrough
4. ด่านล็อกทีละชุดพร้อม parser/UI/state/tests
5. ขัดเกลาจาก playtest และตรึงเวอร์ชันวิจัย

แต่ละชุดต้องอยู่ในสภาพเล่นได้ ไม่เปิดเนื้อเรื่องใหม่ครึ่งหนึ่งกับกฎเก่าอีกครึ่งหนึ่ง การสร้าง commit/push ไม่ได้เกิดขึ้นในรอบวางแผนนี้

## 9. งานวิจัยและขอบเขตที่เลื่อนได้

ใช้ [ข้อกำหนดเป้าหมายและการประเมิน](design-goals-and-evaluation-2026-10-09.md) เป็นเกณฑ์เพิ่มเติม: แยกความถูกต้องของระบบดำเนินเกมออกจากความเข้าใจของผู้เล่น และให้ neural-only รับงานตัดสินความหมายชุดเดียวกับ symbolic โดยไม่มีตัวตรวจ symbolic ช่วยซ่อมผลระหว่างรัน ความซับซ้อนต้องมีสถานการณ์หลายระดับและคำตอบอ้างอิงที่ตรวจแล้ว ไม่ตั้งผลว่ารุ่นใดต้องชนะ

กำหนดสิ่งที่จะวัดและข้อมูลร่วมตั้งแต่ระยะ B ส่วนการเก็บผลจริงทำหลังเนื้อหาและกฎนิ่ง ใช้ฉากเริ่ม กติกา คำใบ้ และนโยบายเวลาเหมือนกัน แยกผลการตีความภาษาออกจากการตัดสินกฎ และมีทั้งคำสั่งที่ควรอนุญาตกับควรปฏิเสธ

ขอบเขตที่ยังไม่รวม: ห้องใหม่ ภาพใหม่ครบทุกวัตถุ ฉากจบเพิ่ม ระบบความสัมพันธ์ บทสนทนาอิสระเต็มระบบ และการเพิ่มปมลับในคดีเก่า รอบนำเข้าเกมได้เพิ่ม neural-only ที่ขอบเขตตัวตัดสินผ่าน CLI แล้ว โดยหน้าเว็บยังเป็น NeSy การเปรียบเทียบผู้เล่นผ่านเว็บสองระบบครบวงจรยังไม่ใช่สิ่งที่ส่งมอบรอบนี้

ลำดับความสำคัญเมื่อเวลาจำกัด: **เหตุและผลของคดี + ปมสองเวลา + คำโกหก → กฎ/บทพูด/ฉากจบที่ตรงกัน → ด่านล็อก → การขัดเกลา**

ยังไม่ให้ประมาณการจำนวนวันจนกว่าจะจบ A2/B และเห็นจำนวนบท หลักฐาน และเส้นทางที่ต้องรองรับจริง
