# Nocturne Express: ชุดทดลองตัวตัดสินและการตรวจความเข้าใจผู้เล่น

วันที่ 12 ตุลาคม 2026

เอกสารนี้กำหนดวิธีใช้สิ่งที่ส่งมอบในรอบนี้ ไม่ใช่รายงานว่า NeSy เหนือกว่า neural-only และยังไม่มีผลทดลองกับผู้เล่นจริง

## 1. สิ่งที่นำมาทดลองได้แล้ว

`scripts/evaluate_modes.py` เปรียบเทียบที่ขอบเขต **สถานะ + คำสั่งที่ตีความแล้ว → คำตัดสิน + สถานะใหม่ + ข้อมูลที่แสดง** มีสองโหมด:

| โหมด | ผู้ตัดสิน | ขอบเขตคำอธิบาย |
|---|---|---|
| `symbolic` | `SymbolicEngine` และกติกายื่นหลักฐานแบบเดียวกับเกม | trace จากกฎที่ถูกตรวจจริง |
| `neural` | `NeuralGameMaster` ให้โมเดลตัดสินทั้งผลการกระทำ บท หลักฐาน การอนุมาน การมองเห็น และฉากจบ | คำอธิบายที่โมเดลกล่าวอ้าง ไม่ใช่ trace ที่พิสูจน์ว่ารันกฎนั้นจริง |

ชื่อ `symbolic` ใน CLI หมายถึงส่วนตัดสินของระบบ NeSy เมื่อควบคุมคำสั่งเข้าแล้ว การรันนี้ไม่ได้วัดการแปลภาษาไทยของ Neural Layer และไม่ใช่การเปรียบเทียบเกมผ่านหน้าเว็บครบวงจร

กรณีเผชิญหน้ากิเดียนใน corpus วัดการเปิดบทและผลต่อสถานะที่ขอบเขตคำสั่งเท่านั้น การเลือกหน้าในฉาก การเปิดย้อนอ่าน และการยินยอมดูบทเล่าย้อนหลังบนหน้าเว็บยังไม่อยู่ใน output schema ของ baseline นี้ จึงต้องทดสอบส่วนเหล่านั้นแยก และห้ามใช้คะแนน corpus อ้างว่าการแสดงฉากของทั้งสองระบบถูกเปรียบเทียบแล้ว

ฝั่ง neural รับข้อมูลโลก กฎ เอกสาร กลไกกลาง และสถานะดิบเดียวกัน ไม่มีการป้อนข้อสรุปหรือรายชื่อวัตถุที่ symbolic คัดให้ ไม่มีการใช้ symbolic ตรวจสิทธิ์ แก้คำตอบ หรือเติมหลักฐานระหว่างรัน การตรวจ JSON จำกัดที่รูปแบบและชนิดข้อมูล คำตอบที่ถูกแบบแต่ใช้ ID ไม่มีจริงหรือสรุปผิดยังคงถูกเก็บและส่งต่อใน rollout

## 2. คำสั่งใช้งาน

จากโฟลเดอร์โครงการ ใน PowerShell:

```powershell
# ตรวจชุดคำตอบอ้างอิงกับตัวตัดสิน symbolic โดยไม่เรียก API
.venv\Scripts\python.exe scripts/evaluate_modes.py --mode symbolic --output logs/research/symbolic-smoke.json

# ทดลองโมเดลจริง ใช้ credentials ที่โครงการตั้งไว้; คำสั่งนี้เรียกบริการและอาจมีค่าใช้จ่าย
.venv\Scripts\python.exe scripts/evaluate_modes.py --mode neural --model YOUR_MODEL_ID --suite one-step --repetitions 3 --output logs/research/neural-one-step.json
.venv\Scripts\python.exe scripts/evaluate_modes.py --mode neural --model YOUR_MODEL_ID --suite rollout --repetitions 3 --output logs/research/neural-rollout.json

# จำกัดกรณีก่อนเริ่มรันใหญ่
.venv\Scripts\python.exe scripts/evaluate_modes.py --mode neural --model YOUR_MODEL_ID --case lock --output logs/research/neural-lock.json

# ทดลองเล่นตัวตัดสิน neural โดยส่งคำสั่ง JSON ตรง ไม่ผ่าน parser/ตัวกรอง symbolic
.venv\Scripts\python.exe scripts/evaluate_modes.py --mode neural --model YOUR_MODEL_ID --play --output logs/research/neural-play.jsonl
```

ตัวอย่างคำสั่งใน `--play`:

```json
{"action":"move","target":"first_class_car"}
{"action":"examine","target":"pocket_watch"}
{"action":"unlock","target":"dossier_bag","code":"1923"}
{"action":"interrogate","target":"car_attendant","topic":"impact"}
```

เลือก ID หัวข้อจาก `data/story.json` รุ่นที่ใช้ทดลอง ทุกตาต้องเป็น JSON หนึ่งคำสั่ง คำสั่งกล่าวหาใช้ `submitted_evidence` ส่วนข้อสรุปใช้ `evidence` ตามสัญญา `ParsedCommand` นาฬิกาใน CLI ถูกควบคุมด้วยสถานะและไม่เดินตามเวลาจริง จึงใช้ตรวจตัวตัดสินและลำดับเหตุการณ์ ไม่ใช้แทนการทดลองเล่นที่จับเวลาจริง

`/state` เป็นเครื่องมือผู้วิจัยสำหรับดูสถานะทั้งหมด ห้ามใช้เป็นหน้าจอผู้เข้าร่วมโดยไม่ออกแบบการทดลองใหม่ ข้อผิดพลาดจากบริการหรือรูปแบบในโหมดเล่นจะหยุด session และบันทึกเหตุการณ์ ไม่มี fallback ไป symbolic

## 3. ชุดคำตอบอ้างอิง

`data/research/adjudication-corpus-v1.json` เก็บคำสั่ง สถานะเริ่ม คำตอบที่คาดหวัง และเหตุผลจากข้อกำหนดเรื่องที่เขียนไว้ล่วงหน้า ใช้คำตอบที่ตรวจจาก A2/กติกา ไม่สร้างคำตอบโดยเรียก engine แล้วถือว่าถูกโดยอัตโนมัติ เมื่อผล symbolic ไม่ตรง ต้องตรวจทั้งคดี กฎ และคำตอบอ้างอิงก่อนเลือกแก้

กรณีครอบคลุมการย้ายห้อง/สิทธิ์เข้าถึง รหัสและกุญแจ การตรวจที่ไม่ปลดล็อก พยานที่กล่าวหาไม่ได้ บทสนทนาซ้ำและบทที่เปิดตามข้อมูล การอ้างหลักฐานที่ยังไม่พบ ข้อสรุปสองเวลา และทางจบทั้งสามคู่ชา/กระดุม/ตรา รวมกรณีใกล้กันที่ควรผ่านกับไม่ควรผ่าน

ชุดนี้เป็น **development corpus ที่ใช้ตรวจงานระหว่างพัฒนา** จึงไม่ใช่ held-out benchmark สำหรับสรุปประสิทธิภาพเชิงวิจัย สถานะบางกรณีเป็นจุดตรวจกลางเกมที่กำหนดไว้ การทดสอบ rollout แยกออกมาเพื่อดูผลสะสมจากการเปลี่ยนสถานะจริง

ไฟล์ corpus และ source bundle มี hash ในรายงาน รุ่น corpus ตรึง hash ของ world/rules/mechanics/documents หากต้นฉบับเปลี่ยน CLI จะหยุด ให้ตรวจคำตอบอ้างอิงและสร้างรุ่นใหม่ก่อนทดลองจริง `--allow-source-drift` อนุญาตงานสำรวจแต่บันทึกว่าข้อมูลไม่ตรงรุ่น ห้ามรวมผลนั้นกับชุดที่ตรึงแล้วโดยไม่รายงาน

ก่อนเก็บผลหลัก ให้ผู้ตรวจอีกคนสร้าง/ตรวจชุด held-out ที่ไม่ใช้แก้ prompt พร้อมกรณีใหม่และลำดับใหม่ แยกชุดปรับระบบกับชุดทดสอบ เก็บผู้ตรวจและข้อขัดแย้งที่แก้แล้วเป็นบันทึก review

## 4. การรันและการอ่านผล

- **One-step:** แต่ละกรณีเริ่มจากสถานะอ้างอิงที่กำหนดใหม่ วัดตัวตัดสินโดยไม่ปะปนความผิดจากตาก่อน
- **Rollout:** ตาถัดไปใช้สถานะที่ระบบคืนเอง แม้ผิดจากเรื่อง ระบบไม่คืนสถานะให้ถูกเพื่อช่วย baseline ผลเทียบกับเส้นทางอ้างอิงระบุ `previous_reference_divergence` เมื่อเคยผิดมาก่อน หลังจุดนั้นความต่างอาจเป็นผลสะสม ไม่ใช่ความผิดใหม่อิสระทุกตา
- **Provider/format errors:** แยกจากคำตอบเชิงความหมายที่ผิด รายงานทั้งอัตราถูกในคำตอบที่อ่านได้ และอัตราสำเร็จเมื่อรวมทุก attempt; rollout ที่อ่านสถานะต่อไม่ได้หยุดและนับจำนวนตาที่ยังไม่รัน
- **เวลาและการใช้บริการ:** เก็บ latency ของแต่ละตา จำนวน attempt token usage/model version เมื่อ provider ส่งมา และ hash ของ prompt/input/bundle โหมด neural เรียกครั้งเดียวต่อตา ไม่มี retry หรือสลับ key อัตโนมัติ ราคา USD เป็น `null` ถ้าไม่ได้คำนวณจากราคาและ usage จริง ห้ามตีความว่าไม่มีค่าใช้จ่าย
- **คะแนนอัตโนมัติ:** ตรวจคำตอบ allowed/denied สถานะครบทุกช่อง และข้อยืนยันเรื่อง deduction/visibility ที่ corpus ระบุ ไม่ถือว่า prose ถูกเพียงเพราะ state ถูก ต้องตรวจข้อความ เฉลยก่อนเวลา ความหนักแน่นเกินหลักฐาน และคำอธิบายไม่ตรงทางที่ยื่นเพิ่มเติม

บันทึก seed หาก provider รองรับ รุ่นโมเดลที่ใช้จริง อุณหภูมิ งบเรียก เวลา timeout และแผนจำนวนรันก่อนทดลอง รายงานความต่างด้านต้นทุนการเรียกโมเดลตามจริง ส่วน latency ของ symbolic ไม่รวม parser; ห้ามเรียกค่านี้ว่าเวลา NeSy ตั้งแต่ผู้เล่นพิมพ์จนเห็นผล

## 5. ตรวจความเข้าใจเนื้อเรื่องควบคู่กัน

ทดสอบต้นแบบกับผู้เล่นที่ยังไม่รู้เฉลยก่อนตรึงเงื่อนไขวิจัย ให้ผู้เล่นเล่นตามปกติ เก็บคำสั่ง การย้อนอ่าน หัวข้อที่ถาม หลักฐานที่ยื่น การใช้คำใบ้ และข้อสรุปที่เลือก เกมผ่านหลักฐานไม่ได้แปลว่าผู้เล่นเข้าใจเหตุผล

หน้าเว็บปัจจุบันแสดงข้อความฉากจบทันทีหลังยื่นคดี ข้อความนั้นบอกข้อสรุปสำคัญแล้ว แม้ผู้เล่นยังไม่เปิดฉากเล่าเหตุการณ์ย้อนหลัง จึงห้ามถือว่าการถามหลังยื่นคดีวัดความเข้าใจก่อนเห็นเฉลยได้

สำหรับต้นแบบนี้ ให้ผู้ดำเนินการทดลองหยุดผู้เล่น **ก่อนกดยืนยันส่งคำกล่าวหา** แล้วใช้คำถามสั้นชุดเดียวกันทั้งสองกลุ่ม บันทึกชุดหลักฐานและผู้ต้องสงสัยที่ผู้เล่นตั้งใจเลือก ณ จุดนั้น ก่อนอนุญาตให้ส่งคดีและเห็นผล วิธีนี้ยังเป็นขั้นตอนที่ผู้ดำเนินการต้องจัดเอง หน้าเว็บยังไม่มี study mode ที่พักผลคดีเพื่อรับแบบสอบถาม หากต้องการเก็บหลังส่งแต่ก่อนเห็นผล ต้องสร้างและตรวจ study mode ดังกล่าวก่อนทดลอง:

1. เล่าเหตุการณ์คืนนี้ตามลำดับที่คุณเชื่อ พร้อมบอกว่าข้อมูลใดทำให้คุณจัดลำดับเช่นนั้น
2. เหตุใดคุณจึงเลือกหรือไม่เลือกกล่าวหาวินเซนต์? ข้อมูลใดสำคัญต่อการตัดสินนั้น?
3. การนั่งกับกิเดียนในตู้เลานจ์ช่วยยืนยันอะไรได้บ้าง และยังมีอะไรที่คุณไม่รู้?
4. แฟ้มที่แคสเซียนเตรียมส่งเกี่ยวข้องกับเหตุการณ์คืนนี้อย่างไร?

เกณฑ์แต่ละข้อ 0–2: **0** ไม่ตอบ/ขัดข้อเท็จจริงสำคัญ; **1** อธิบายส่วนหนึ่งถูกแต่เชื่อมหลักฐานหรือขอบเขตไม่ครบ; **2** อธิบายความสัมพันธ์ถูกพร้อมหลักฐานและขอบเขตที่เกี่ยวข้อง ห้ามให้คะแนนตามการใช้ถ้อยคำเดียวกับบทเฉลย ผู้ตรวจไม่ควรรู้กลุ่มระบบของคำตอบ และต้องทดลองใช้ rubric กับคำตอบนำร่องก่อนตรึง

ข้อสรุปที่ผู้เล่นเลือกในเกมเป็นหลักฐานเสริม ไม่แทนคำอธิบายปลายเปิด เพราะเมนูช่วยชี้แนวคิดให้แล้ว แยกแบบประเมินความสนุก ความเป็นธรรม ความสับสน และเวลาเล่นจริงออกจากคะแนนความเข้าใจ เลือกจำนวนผู้เล่น/สถิติโดยอิงคำถามวิจัยและข้อมูลนำร่อง ไม่กำหนดจากจำนวนเบาะแสในเกม

ในการเทียบผู้เล่นครั้งแรกของคดีเดียวกัน ให้แยกกลุ่มหรือควบคุมผลการเรียนรู้ ผู้ที่รู้เฉลยจากอีกระบบแล้วไม่ใช่ผู้เล่นใหม่ของอีกฝั่ง ทั้งสองกลุ่มต้องได้รับหน้าจอ คำใบ้ ข้อความนำ และเงื่อนไขเวลาเท่าเทียมกัน การทดลองผู้เล่นผ่านหน้าเว็บ neural-only ต้องตรวจว่าหน้าเว็บไม่เรียก symbolic ในการมองเห็น บท สมุดคดี หรือฉากจบด้วยก่อนเริ่มเก็บผล

ฉากเปิดเรื่องอ่านได้ก่อนเริ่มนาฬิกาสืบสวน ให้ทั้งสองกลุ่มมีสิทธิ์อ่านและข้ามเหมือนกัน และเก็บเวลาอ่านแยกจากเวลาในคดี ฉากเผชิญหน้ากิเดียนเปิดเมื่อผู้เล่นบันทึกข้อสันนิษฐานสองเวลาอย่างมีหลักฐานแล้วและตรวจต้นทางข่าวเลื่อนนัดสำเร็จ จึงนับเป็นการสอนหรือย้ำความเข้าใจระหว่างเล่น ไม่ใช่มาตรวัดที่ไม่มีผลต่อผู้เล่น

ฉากเล่าเหตุการณ์ย้อนหลังเป็นการเปิดอ่านโดยสมัครใจหลังฉากจบแท้เท่านั้น การดูฉากนั้นไม่อยู่ในคะแนนความเข้าใจก่อนเฉลย หากต้องการศึกษาว่าฉากช่วยให้เข้าใจมากขึ้น ให้ถามและรายงานผลหลังฉากเป็นผลอีกชุดหนึ่งพร้อมบันทึกว่าผู้เล่นเลือกดูหรือข้าม ไม่รวมเข้ากับผลก่อนส่งคดี

## 6. ข้อจำกัดและสิ่งที่ยังต้องเก็บจริง

การส่งมอบโค้ดและผ่าน offline tests ยืนยันความพร้อมของเส้นทางเรียกและการเก็บข้อมูล ไม่ยืนยันว่ารุ่นโมเดลใดทำงานได้ดีหรือเกมสนุก การทดสอบด้วย stub ใช้ตรวจว่าไม่มีการซ่อม semantic response และ error ถูกจำแนก ไม่ใช้แทนผล neural จริง

ยังต้องรัน provider ที่เลือก เก็บผลซ้ำบนชุด held-out ตรวจคำตอบ prose และทดลองกับผู้เล่นจริงก่อนสรุปเรื่องความถูกต้อง ความเข้าใจ หรือความสนุก งานนี้ไม่ตั้งสมมติฐานเป็นผลล่วงหน้าว่า neural-only ต้องแพ้

## 7. สถานะการตรวจส่งมอบ 13 ตุลาคม 2026

- Adapter tests แบบ offline ผ่าน 12 ข้อ รวมการเก็บ semantic mistake โดยไม่ซ่อม การส่งสถานะผิดต่อใน rollout และการแยก provider/schema error
