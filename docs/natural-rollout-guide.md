# ทดสอบ Neural กับ Neuro-symbolic แบบเล่นต่อเนื่อง

สคริปต์หลักคือ `scripts/run_natural_rollout.py` รองรับคดี A โดยอ่านจำนวนคำสั่งจาก `data/walkthrough.json` ปัจจุบันมี 28 คำสั่ง ไม่ต้องแก้จำนวนในโค้ดเมื่อเพิ่มขั้นตอน

## วิธีทดลอง

1. อ่าน walkthrough และข้อมูลคดี สร้างข้อความภาษาไทยจากชื่อวัตถุ/สถานที่และหัวข้อสนทนา ข้อความนี้เป็นคำสั่งจากเส้นทางพัฒนา ไม่ใช่ข้อความที่เก็บจากผู้เล่นอิสระ
2. ตรวจเส้นทางอ้างอิงด้วย Symbolic engine ก่อนเริ่ม เพื่อยืนยันว่าเส้นทางที่เตรียมไว้จบคดีได้ ผลอ้างอิงไม่ส่งให้โมเดล
3. เริ่มแต่ละระบบจากสำเนาสถานะเริ่มเกมเดียวกัน ใช้ข้อความชุดเดียวกันและลำดับเดียวกัน
4. ในทุกตา เรียก Gemini ตีความข้อความโดยใช้สถานะของระบบนั้นเอง ไม่มี fast-path หรือการแก้คำสั่งด้วยเฉลย
5. Neural เรียก Gemini อีกครั้งเพื่อตัดสินและสร้างสถานะใหม่ ส่วน Neuro-symbolic ใช้ Symbolic engine ตรวจและเปลี่ยนสถานะ
6. เก็บสถานะที่แต่ละระบบสร้างไว้จริงไปใช้ในตาถัดไป รวมถึงสถานะที่ผิด ไม่แทนด้วยสถานะอ้างอิง
7. ตรวจสองอย่างแยกกัน: ผลตรงกับเส้นทางอ้างอิงหรือไม่ และผลสอดคล้องกับกฎจากสถานะของระบบเองก่อนตานั้นหรือไม่ อย่างหลังช่วยแยกข้อผิดพลาดใหม่จากผลสะสม
8. หยุดเมื่อมีฉากจบ ใช้คำสั่งครบ หรือบริการ/รูปแบบคำตอบผิดพลาด ถ้าบริการขัดข้องสามารถ resume โดยเก็บประวัติเดิมไว้ ไม่มีการลองคำตอบผิดกฎใหม่เพื่อเลือกคำตอบที่ดีขึ้น

## คำสั่งรันใน PowerShell

เปิด PowerShell ในโฟลเดอร์โครงการ ใช้โฟลเดอร์ผลลัพธ์ใหม่ทุกครั้ง

ตรวจออฟไลน์ ไม่ใช้ API:

```powershell
.venv\Scripts\python.exe scripts\run_natural_rollout.py --output results\natural-rollout\check-new
```

ทดลองจริง โดยใช้ Gemini ที่ตั้งค่าไว้ในเครื่อง:

```powershell
.venv\Scripts\python.exe scripts\run_natural_rollout.py --live --output results\natural-rollout\run-new
```

ปัจจุบันแผนคือ 84 คำขอ: Neural ตีความ 28 + ตัดสิน 28 และ NeSy ตีความ 28 กำหนดเพดานรวม 168 ครั้ง และลองซ้ำหนึ่งครั้งต่อคำขอเฉพาะบริการขัดข้องชั่วคราว เว้นระยะปกติ 5 วินาที ไม่มีโมเดลสำรองหรือ symbolic fallback สำหรับ Neural

ถ้าหยุดเพราะบริการขัดข้อง เล่นต่อในโฟลเดอร์เดิม:

```powershell
.venv\Scripts\python.exe scripts\run_natural_rollout.py --live --resume --output results\natural-rollout\run-new
```

Resume ตรวจว่าข้อมูลและคำสั่งเดิมไม่เปลี่ยน และนับคำขอเก่ารวมในเพดานเดิม ถ้าเกมเปลี่ยนเวอร์ชัน ให้เริ่มรอบใหม่

สร้างสรุปจาก log ทั้งหมด รวมช่วงที่ resume:

```powershell
.venv\Scripts\python.exe scripts\summarize_natural_rollout.py results\natural-rollout\run-new
```

## ไฟล์ที่เปิดให้อาจารย์ดู

| ไฟล์ | ใช้ตรวจอะไร |
|---|---|
| `inputs.json` | ข้อความทุกข้อ สถานะเริ่มต้น และข้อมูลเกมที่ใช้ |
| `manifest.json` และ `code-snapshot/` | รุ่นโมเดล แผนทดลอง และโค้ดที่ใช้ |
| `requests.jsonl` | พรอมป์ต์ คำขอ คำตอบดิบ usage เวลา และข้อผิดพลาดทุกครั้ง |
| `neural/parser.jsonl`, `neuro-symbolic/parser.jsonl` | ข้อความถูกตีความเป็น action/target/topic อย่างไร |
| `neural/turns.jsonl`, `neuro-symbolic/turns.jsonl` | สถานะก่อน–หลัง การอนุญาต และผลตรวจรายตา |
| `reference.json` | ผลเส้นทางอ้างอิงสำหรับตรวจย้อนหลัง |
| `benchmark-summary.json`, `comparison.csv`, `report-th.md` | สรุปรวมทุกช่วงการรันและตารางเปิดใน Excel |

ใช้ `benchmark-summary.json` จากตัวสรุปเป็นตัวเลขหลัก เพราะรวมคำขอและข้อผิดพลาดจากทุกช่วงที่เล่นต่อแล้ว ข้อผิดพลาด API แยกจากความผิดด้านกฎ

## ข้อจำกัดในการอธิบายผล

ผล 28 คำสั่งใช้เกมและกลไก v3 ที่เพิ่ม `requires_examined` จึงแยกจากผลเก่า 25 คำสั่ง ไม่รวมคะแนนเป็นชุดเดียวกัน ตัวตรวจใช้ engine เดียวกับ NeSy ไม่ใช่ผู้ประเมินอิสระ และยังไม่ตรวจข้อความบรรยายว่ารั่วข้อมูลหรือไม่ คะแนนตีความแบบ exact-field ตรวจช่องที่กำหนดในสคริปต์ ไม่ใช่การประเมินความเข้าใจภาษาทุกมิติ

คำว่า `true_ending` ที่โมเดลรายงานต้องดูคู่กับผลตรวจการกระทำสุดท้ายและสถานะสุดท้าย ไม่ใช่อาศัยข้อความฉากจบเพียงอย่างเดียว
