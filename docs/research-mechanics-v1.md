# Shared adjudication semantics v1

This is the explicit mechanics contract supplied as source information to the neural game master. It contains no state-specific answers. It must be versioned with the world and benchmark when mechanics change. The implementation is in `app/symbolic/engine.py`; the neural runtime does not import or execute it.

- A turn processes one ParsedCommand. `unknown`, `ambiguous`, and unexpanded `sequence` are not executable. Confidence never authorizes an action.
- Evaluate blocking rules in the order in `rules.rules`. `applies_to: ["*"]` applies to every action. A failed nonblocking rule can be reported but does not stop the action. `claimed_rule_id` is the first failed blocking rule, or null when allowed.
- `game_not_over`: reject when ending_id is set. `within_time_limit`: reject when elapsed_seconds is greater than or equal to the world's time_limit_seconds; select the world's timeout ending. Do not advance controlled time merely because a request happened.
- Targets must exist. Move targets must be locations and must not be restricted. Interrogate targets must be people in suspects, including witnesses; accuse targets must be accusable suspects, never people with accusable=false.
- For examine/take/unlock/use/burn/interrogate the target must be at current_location, have no physical location (for already acquired testimony), or be carried in inventory. Looking at another location requires moving there first.
- A from_testimony object can only be examined after that person has been interrogated AND that particular evidence is discovered. Naming an evidence ID in a command never grants it.
- The supports list explicitly authorizes take/unlock/use/burn for that object. Examination never unlocks an object. `visible_requirements` checks all requires_evidence, requires_deductions, requires_unlocked, requires_inventory and earned requires_claims plus any at_least/of condition. A burned target cannot be accessed. Contained objects declare their parent through requires_unlocked; do not reveal or grant them merely by naming them.
- Both unlock and use target the locked object/door. It must have unlock_requirements. Check evidence/deduction/unlocked/inventory/earned-claim prerequisites, then exact string command.code if a code is required, then command.instrument equals the required key AND the key is in inventory. An already unlocked target succeeds without rechecking its key/code. A use action on the key itself does not redirect to a door. Correct unlock/use adds only unlocked_objects, never all contents.
- Deduction conditions are conjunctive: all requires_evidence, all requires_deductions, and at least `at_least` entries from `of` are required. The `of` entries can be evidence or deductions. Continue chained inference until no new deduction is supported. No missing-alibi inference establishes presence. Use only discovered_evidence for deductions; raw_text is not evidence.
- Infer uses command.target as a claim ID and command.evidence as the submitted support. The claim must be offered by an inference_question whose prerequisites are satisfied in the current state. The evidence list must be nonempty, unique and fully known. The claim must declare supported=true and its evidence/deduction requirements must hold using ONLY the submitted support. Supported inference adds validated_claims and stores exactly that evidence list in claim_evidence; it does not discover new facts. Unsupported inference changes nothing.
- A previously validated claim counts only if it is in validated_claims, has a nonempty recorded support list, and the intersection of that recorded support with the evidence currently under consideration still meets the claim requirements. For an accusation's submitted subset, necessary recorded support must remain; optional extra evidence from the earlier inference may be omitted. Do not silently replace the player's recorded support with other newly known evidence. A label in validated_claims alone is insufficient. Every requires_claims gate uses this earned-claim check, including dialogue nodes, object visibility, unlock requirements and inference-question availability; merely possessing enough evidence is not equivalent to having recorded the supported inference.
- Pillars use world.pillar_order. For a suspect/pillar, requires_deductions must be nonempty, all those deductions and all requires_claims must be supported; otherwise that pillar is empty. Report the configured supported deduction IDs in each pillar in configured order.
- An ending matches only its accused person (or wildcard), all positive evidence/deduction/pillar/claim requirements, and none of its denies_evidence/denies_deductions/denies_pillars. A wildcard fallback alone cannot authorize an accusation. Select the first matching ending in ending_order. Four-pillar feedback does not replace the declared ending conditions.
- First enforce terminal state/time before handling an accusation submission. Accusations require an explicit nonempty submitted_evidence list with no duplicates, at most world.max_submitted_evidence items (legacy default 15), all already discovered. Invalid submission format is R_SUBMITTED_EVIDENCE and does not consume a failed attempt. First check accusation eligibility on ALL known evidence so that a suspect's exculpatory_deductions or exculpatory_evidence cannot be evaded by omitting them; then check the submitted subset. Keep all discovered evidence in resulting state. If a legitimate submission fails R012_ACCUSE_ENDING_REQUIREMENTS, add one failed accusation; the third failed accusation closes as unproven and records failed_accusations=3. Wrong accusations that satisfy a declared ending close immediately. Support the explanation using only the submitted evidence, except known exculpatory facts that prevent the accusation. An R016_ACCUSABLE rejection does not consume a failed attempt.
- An allowed action increments turn_count once. Move sets current_location and adds visited_locations once. Examine a non-location adds examined_objects and, for evidence, discovered_evidence; examining a location changes neither discovery nor examined_objects. Take adds inventory and, for evidence, discovery, but does not add examined_objects. Unlock/use adds unlocked_objects only after checking requirements. Burn adds burned_objects and removes the object from inventory, without erasing prior discovery. Accuse sets ending_id. Preserve list insertion order and append once; repeated entries do not duplicate list values.
- A denied action leaves the state unchanged except explicitly declared timeout/failed-accusation effects; it does not increment turn_count. Preserve started_at and elapsed_seconds in this controlled boundary.
- A person's dialogue_nodes are eligible only when their evidence/deduction/unlocked/inventory/earned-claim requirements pass. For a command.topic select the LAST eligible node with that topic; an unavailable topic fails. Without a topic select the FIRST eligible unseen node (history token personID:nodeID), or the LAST eligible node when all are seen. Only that node's text and grants_evidence/grants_inventory are delivered. Add that history token and interrogated_suspects. Ignore a person's aggregate grants_evidence/testimony when dialogue_nodes exists: those legacy fields do not authorize later-node grants. Repeated dialogue must not grant another node's evidence. For legacy people without dialogue_nodes, absent topic uses testimony, grants_evidence and grants_object; a supplied topic fails. Do not expose a character's secret knowledge before its discovery conditions.
- Narrative scenes are authored presentation content, not evidence-granting actions. At this parsed-command boundary, interrogation still returns the selected node's message and normal state effects; do not automatically render an entire referenced scene or the optional post-ending reconstruction. Browser page selection/replay and consent to opening a reconstruction are outside this output schema and benchmark. Source narrative pages never authorize otherwise unavailable dialogue or knowledge.
- Visible objects are in the current location, not carried, and examinable under the same access rules. Visible people are people in the current location. These views are selected by the model in neural-only mode, not filtered by the symbolic engine. Descriptive claims and explanations are generated claims, not executed traces.

The concrete dialogue/claim/lock field names are described in the world data and the updated schema. The benchmark is controlled at the parsed-command boundary, not at the web/API layer. No automatic semantic repair is permitted for neural-only results.
