## งานของคนทำ Frontend

branch `frontend` ยัง merge ไม่ได้ มีสองเรื่องที่ต้องแก้ก่อน และห้าอย่างที่หายไป

### ต้องแก้ก่อน merge

**1. ตัว simulator ที่แต่ง reasoning chain ปลอม** — `frontend/chat.js` บรรทัดราว 467 ถึง 620

เวลา backend error โค้ดจะเงียบๆ สลับไปใช้ตัวจำลอง แล้วสร้างสายเหตุผลขึ้นเองด้วยรหัสกฎที่
**ไม่มีอยู่จริงใน `data/rules.json`** เช่น `R01_PRESENCE`, `R04_CLUE_DISCOVERY`,
`R15_ACCUSATION_GROUNDING`, `R16_CASE_SOLVED`

ปัญหาคือคนดูแยกไม่ออกว่าอันไหนของจริงอันไหนของปลอม และมันคือการอธิบายย้อนหลัง
ซึ่งเป็นสิ่งที่งานวิจัยนี้ตั้งใจจะชี้ว่าเป็นปัญหา ถ้าอาจารย์เห็นตอน backend ล่ม จะกลายเป็นว่า
ระบบโชว์เหตุผลที่ระบบไม่ได้ใช้จริง

**ทางแก้** ถ้า backend เรียกไม่ได้ ให้แสดงข้อความว่าเชื่อมต่อไม่ได้ไปตรงๆ ห้ามเดาผลลัพธ์แทน

**2. `API_BASE` ตรึงไว้ที่ localhost**

```js
// branch frontend ตอนนี้
const API_BASE = "http://127.0.0.1:8000";

// ต้องเป็นแบบนี้ ไม่งั้นขึ้นเว็บจริงแล้วเบราว์เซอร์จะยิงไปที่เครื่องคนเล่นเอง
const API_BASE = window.location.protocol.startsWith("http") ? "" : "http://127.0.0.1:8000";
```

### ของที่หายไปตอนเขียน UI ใหม่ ต้องเอากลับ

## งานฝั่งระบบ

### 1. ไม่มีเทสที่เรียก LLM จริงเลยสักข้อ

`tests/test_neural.py` มี 5 ข้อ แต่ทุกข้อเป็นการตรวจ prompt กับ schema ล้วน
ไม่มีข้อไหนเรียก `interpret()` จริง ทั้งไฟล์รันจบใน 0.4 วินาที
แปลว่าถ้าชั้น neural พังจะไม่มีอะไรจับได้

ควรมีอย่างน้อย 3 ถึง 5 ข้อที่ยิงจริง แล้ว skip เองเมื่อโควตาหมด เช่น

```
ตรวจนาฬิกาพกของผู้ตาย   -> examine pocket_watch
ไปห้องระบบไฟฟ้า          -> move luggage_van_electrical
ขอคุยกับหมอหน่อย         -> interrogate dr_liora_venn
```
(ทั้งสามอันนี้ทดสอบด้วยมือแล้วผ่าน แต่ยังไม่มีใครล็อกไว้ในเทส)

### 2. สเปกยังทำไม่ครบสามข้อ

| ข้อ | เนื้อหา | สถานะ |
|---|---|---|
| R-SYS-02 | player claim ไม่ใช่ fact | ยังไม่มี action ให้เสนอสมมติฐาน พิมพ์ว่า วินเซนต์ฆ่าแคสเซียน จะได้ `unknown` |
| R-SYS-04 | ขอบเขตความรู้ของ NPC | `testimony` เป็นข้อความเดียวตายตัว ไม่ได้กรองว่าใครควรรู้อะไร |
| R-SYS-05 | discovered ไม่เท่ากับ identified ไม่เท่ากับ linked | เจอของแล้วถือว่ารู้ทันที ไม่มีขั้น ยังไม่รู้ว่าเป็นของใคร |

ทั้งสามข้อต้องเพิ่ม action หรือเพิ่มสถานะ กระทบทั้งระบบ
แนะนำให้ทำหลังเนื้อเรื่องนิ่งแล้ว และควรตัดสินใจร่วมกันก่อนว่าจะเอาข้อไหน

### 3. action สี่ตัวประกาศไว้แต่ไม่มีกฎคุม

`take` `use` `unlock` `burn` ยังอยู่ใน `ActionType` และอยู่ใน `applies_to` ของกฎทั่วไป
แต่ไม่มีกฎเฉพาะทางคุมเลย เช่นหยิบอะไรก็ได้ เผาอะไรก็ได้ เพราะ checker ที่เคยคุม
ถูกลบไปตอนเคลียร์ระบบ

**ต้องตัดสินใจ** ฉากนี้ใช้ action พวกนี้หรือเปล่า
ถ้าไม่ใช้ ตัดออกจาก `ActionType` กับ `rules.json` ให้หมด
ถ้าใช้ ต้องเขียน checker กลับมา

### 4. เอกสารในเกมยังไม่ถูกใช้หนึ่งไฟล์

`data/documents/` มีสามไฟล์ ผูกกับของในเกมแล้วสองไฟล์

| ไฟล์ | ผูกกับ |
|---|---|
| `burnt_memo_fragment.md` | `burnt_folder_c` |
| `autopsy_report.md` | `secret_file` |
| `voss_telegram_draft.md` | **ยังไม่ได้ผูกกับอะไร** |

ตัวโทรเลขของวอสส์เป็นหลักฐานสำคัญในเนื้อเรื่อง 1923 แต่ตอนนี้ผู้เล่นเข้าไม่ถึงเลย
ต้องตัดสินใจว่าจะให้เจอที่ไหน หรือจะไม่ใช้

## งานที่ต้องทำในหน้าเว็บ Render

4. เสร็จแล้วค่อยลบ branch `draft1` ทิ้ง

## บทพูดตัวละคร

ตอนนี้มีบทพูดครบสามคนแล้ว เกมจึงเล่นได้เต็มระบบ
แต่เป็นชุดที่เขียนไว้ให้ระบบเดินได้ก่อน **เปลี่ยนทับได้ทันที**

ถ้าจะเขียนใหม่ อ่านข้อกำหนดใน `docs/dialogue_brief.md`
แก้แค่ฟิลด์ `testimony` ของแต่ละคนใน `data/story.json` ไม่กระทบตรรกะเลย
เพราะหลักฐานผูกกับ `grants_evidence` ซึ่งแยกจากตัวข้อความ

**ข้อบังคับสองข้อ** มีเทสคอยตรวจอยู่
- ทุกคนต้องมี `testimony` และต้องไม่ตกไปใช้ข้อความสำรอง
- บทพูดห้ามเอ่ยชื่อเต็มของหลักฐานที่ตัวเองไม่ได้ให้ ไม่งั้นตัวละครเฉลยเกมแทนผู้เล่น
