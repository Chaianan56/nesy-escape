# Nocturne Express — ความซับซ้อนของคดี ความเข้าใจของผู้เล่น และการเปรียบเทียบระบบ

วันที่ 9 ตุลาคม 2026 · ข้อกำหนดออกแบบเพิ่มเติมตามเป้าหมายที่ผู้ใช้ชี้แจง

สถานะ: แนวทางสำหรับระยะ B และการออกแบบการทดลอง ยังไม่ได้แก้เกม สร้าง neural-only หรือเก็บผลทดลอง

ใช้ร่วมกับ [ข้อเท็จจริง A2](phase-a-fact-sheet-v2-2026-10-09.md) และ [แผนดำเนินงาน](implementation-plan-2026-10-09.md) เอกสารนี้ปรับเกณฑ์การออกแบบ โดยคงเหตุการณ์และตัวละครที่เลือกไว้ใน A2

## 1. เป้าหมายที่ต้องทำให้สำเร็จคู่กัน

ผู้ใช้ต้องการคดีที่มีความซับซ้อนเพียงพอสำหรับเปรียบเทียบ NeSy กับ neural-only ที่ไม่มีตัวตัดสินกฎ symbolic และต้องการให้ผู้เล่นค่อย ๆ เข้าใจเรื่องระหว่างเล่น

จึงต้องออกแบบทั้ง **ความสัมพันธ์ที่ระบบต้องรักษาให้ถูกต้อง** และ **ลำดับที่ผู้เล่นสร้างความเข้าใจ** ทุกสถานการณ์สำคัญใน B ต้องบอกได้ว่าทดสอบความสามารถใดของระบบ และทำให้ผู้เล่นเข้าใจอะไรเพิ่ม

การปิดช่องโหว่ใน A2 เป็นฐานให้ทดสอบได้ว่าคำตอบใดถูกตามเรื่อง ความยากควรมาจากการประกอบข้อมูลที่สอดคล้องกัน การตรวจต้นทางคำพูด และการปรับข้อสงสัยเมื่อมีข้อมูลเพิ่ม หากความยากเกิดจากข้อมูลขัดกันเอง ผู้ประเมินจะตัดสินผลระบบและผู้เล่นได้ไม่ชัด

ไม่จำเป็นต้องรื้อ A2 หรือคืนปมผู้โดยสารคนที่แปด แต่ห้ามลดความลึกของการอนุมานเพียงเพื่อให้ใช้วัตถุหรือเงื่อนไขน้อยลง จำนวนชื่อและความยาวเอกสารเป็นภาระข้อมูลอีกประเภทหนึ่ง ต้องแยกจากความซับซ้อนของเหตุผลในการทดลอง

## 2. สถานการณ์ที่ใช้ความซับซ้อนของเรื่องจริง

| สถานการณ์จาก A2 | สิ่งที่ผู้เล่นค่อย ๆ เข้าใจ | สิ่งที่ระบบต้องตัดสินให้ถูก |
|---|---|---|
| นาฬิกาพก 20:25 / ไฟดับ 21:15 | นาฬิกาบันทึกคนละเหตุ เมื่อเทียบเสียงกระแทก รอบบริการ และฉาก จึงทบทวนที่อยู่ของกิเดียนได้ | ข้อมูลหนึ่งชิ้นยังไม่พอระบุเวลาโจมตี; มีชุดรองรับแล้วจึงอนุมานลำดับ โดยไม่อ้างเวลาตายแน่นอนจากเข็มนาฬิกา |
| ข่าวเลื่อนนัด / พนักงานปฏิเสธ | ผู้เล่นจำคำพูดถูก แต่เชื่อแหล่งข่าวผ่านกิเดียนมาอีกทอดหนึ่ง | ความทรงจำผู้เล่นกับคำยืนยันกิเดียนอาจมาจากต้นทางเดียวกัน ห้ามนับเป็นพยานอิสระสองคน; แยกความขัดแย้งของคำอ้างออกจากข้อเท็จจริงฆาตกรรม |
| เศษ C / เลขเอกสาร / ทะเบียน / หนังสือนำส่ง | สิ่งที่ถูกเผาเชื่อมการปกปิดเก่ากับเหตุที่กิเดียนต้องหยุดการส่งแฟ้มคืนนี้ | สรุปแรงจูงใจเมื่อเชื่อมข้อมูลครบ ไม่ใช้ G.H. หรือแฟ้มที่หายไปอย่างเดียวระบุคนผิด |
| ลิโอราปิดบังเรื่องบิดา / สมุดรักษา / ผู้ป่วย | ความลับอธิบายความไม่ไว้ใจรัฐ ส่วนที่อยู่ต้องตรวจอีกสาย และต้องครอบคลุมช่วงเหตุ | แยกแรงจูงใจ ความลับ และโอกาส; ไม่มีที่อยู่ยังไม่เท่ากับพิสูจน์ว่าอยู่ที่เกิดเหตุ |
| วินเซนต์ตัดไฟ / คราบเลือด / ข้อมูลสถานี | ผู้ต้องสงสัยทำผิดเรื่องขโมยและไฟดับจริง แต่ข้อมูลนั้นไม่ได้พิสูจน์ว่าเป็นผู้ฆ่า | ข้อสรุป “หลักฐานยังไม่พอกล่าวหาฆาตกรรม” ต่างจาก “มีหลักฐานที่อยู่หักล้างแล้ว”; ต้องตรวจข้อมูลที่รู้แล้วแม้ผู้เล่นไม่ได้แนบทั้งหมด |
| ชา กระดุม และตรา เลือกสองสาย | ผู้เล่นสร้างคดีได้หลายทาง โดยเข้าใจว่าการมาพบยังต้องประกอบกับเวลาและแรงจูงใจ | ทั้งสามคู่ต้องผ่านได้เมื่อประเด็นอื่นครบ; คำอธิบายใช้เฉพาะหลักฐานในทางที่ยื่น ไม่กล่าวถึงกระดุมในคดีที่ใช้ชา+ตรา |

ข้อมูลใหม่ในหลายกรณีเปลี่ยน **ความเกี่ยวข้องของข้อเท็จจริงเดิม**: กิเดียนยังอยู่กับผู้เล่นตอนไฟดับจริง แต่ข้อมูลนั้นไม่คุ้มกันช่วงก่อนขึ้นรถ ไม่ต้องทำให้ข้อเท็จจริงเดิมกลายเป็นเท็จเพื่อสร้างจุดพลิก

## 3. ทำให้เข้าใจผ่านการเล่น

แต่ละช่วงให้คำถามหลักหนึ่งเรื่อง มีการกระทำที่ค้นคำตอบได้ และมีผลต่อความเข้าใจคดี:

| ช่วง | คำถามนำ | การค้นพบและผลต่อเรื่อง |
|---|---|---|
| ขึ้นรถและรอ | ทำไมฉันจึงรออยู่กับกิเดียน? | ผู้เล่นได้รับนัดเดิม ข่าวเลื่อนนัด และประสบการณ์ไฟดับตั้งแต่บทนำ ไม่ซ่อนความทรงจำของตัวผู้เล่นเอง |
| ตรวจที่เกิดเหตุ | นาฬิกาสองเรือนกำลังบอกอะไร? | ตรวจฉากแล้วคุยคนที่รู้เหตุแต่ละอย่าง เพื่อเริ่มแยกเหตุรุนแรงออกจากไฟดับ |
| ตรวจคำให้การ | ใครรู้เรื่องนี้ด้วยตัวเอง และใครฟังต่อมา? | กลับไปหาต้นทางข่าวและเทียบเวลา ความน่าเชื่อถือของคำอ้างเปลี่ยนตามหลักฐาน |
| เชื่อมคดีเก่า | ทำไมคนเหล่านี้จึงต้องการแฟ้ม? | แฟ้มและบทพูดเปิดแรงจูงใจคนละแบบ: ปกปิดความผิด คืนความน่าเชื่อถือให้บิดา และทวงต้นฉบับคืน |
| ส่งคดี | ข้อมูลใดรองรับข้อกล่าวหาของฉัน? | เลือกหลักฐานและทบทวนเหตุผลที่อยู่เบื้องหลังการเลือก ให้ฉากจบตอบต่อคดีที่ยื่นจริง |

นี่คือลำดับความเข้าใจที่มุ่งหวัง ไม่ใช่การบังคับเดินห้องตามลำดับตายตัว บทสนทนาต้องรองรับการพบหลักฐานก่อนหรือหลังคุยกับตัวละคร

สมุดคดีแยกข้อความที่ตรวจพบ คำให้การพร้อมชื่อแหล่ง และสมมติฐานของผู้เล่น ใช้คำถามช่วยจำโดยไม่เติมข้อสรุปที่ผู้เล่นยังไม่ได้สร้าง บทพูดเปลี่ยนตามข้อมูลที่มี แต่ไม่ให้ตัวละครเฉลยสายเหตุผลทั้งหมดหลังคลิกเดียว

ต้นแบบ B ควรมีจุดให้ผู้เล่นใช้ความเข้าใจ เช่น เลือกประเด็นถามกลับหรือแนบหลักฐานเพื่อทักท้วงคำอ้าง ต้องบันทึกว่าผู้เล่นเลือกอะไร ไม่ถือว่าการพบหลักฐานครบเท่ากับผู้เล่นเข้าใจแล้ว การบังคับเขียนคำอธิบายยาวหรือเพิ่มระบบให้คะแนนภาษาธรรมชาติยังไม่ใช่ข้อกำหนดรอบนี้

## 4. สิ่งที่สถาปัตยกรรมปัจจุบันวัดได้

จาก `app/neural/__init__.py` Neural แปลข้อความผู้เล่นเป็นคำสั่ง ส่วน `app/symbolic/engine.py` ตรวจเงื่อนไขและคำนวณข้อสรุปจากชุดหลักฐาน ฟังก์ชัน `deductions_held` คำนวณข้อสรุปต่อเนื่องจนไม่มีข้อใหม่ โดยไม่ได้ตรวจว่าผู้เล่นอธิบายเหตุผลนั้นได้หรือไม่

ดังนั้นคำถามวิจัยหลักที่เสนอคือ **เมื่อเงื่อนไขของคดีซับซ้อนขึ้น การมีตัวตัดสินกฎ symbolic ส่งผลต่อความถูกต้องและความสม่ำเสมอของระบบดำเนินเกมอย่างไร** ส่วนความเข้าใจเรื่องของผู้เล่นเป็นคำถามอีกส่วนที่ต้องวัดจากผู้เล่น

ผลระบบรักษากฎได้ดีขึ้นเพียงอย่างเดียวไม่รองรับข้ออ้างว่า AI เข้าใจเรื่องดีกว่า ผู้เล่นเข้าใจมากกว่า หรือเกมสนุกกว่า และไม่ตั้งผลล่วงหน้าว่า neural-only ต้องแพ้

## 5. ขอบเขตการเทียบที่เสนอสำหรับ B

- **NeSy:** Neural ตีความคำสั่ง แล้ว symbolic ตัดสินความชอบด้วยกฎ ข้อมูลที่เปิดได้ การมอบหลักฐาน ข้อสรุป การเปลี่ยนสถานะ และผลคดี
- **Neural-only:** ให้โมเดลรับหน้าที่ตัดสินความหมายข้างต้นจากข้อมูลคดี กติกา และสถานะชุดเดียวกัน โดยไม่มีตัวตรวจ symbolic ช่วยอนุมัติ ซ่อม หรือเลือกผลให้ระหว่างรัน
- **ส่วนกลางที่ใช้ร่วมกันได้:** หน้าจอ การจัดเก็บข้อมูล การตรวจรูปแบบ JSON และการแสดงข้อความตามผลที่ระบบเลือก การตรวจรูปแบบต้องไม่แอบตรวจว่ามีสิทธิ์ได้หลักฐานหรือว่าคดีครบแล้ว
- **ความเท่าเทียมของข้อมูล:** บทบาทผู้ดำเนินเกมทั้งสองแบบได้รับข้อกำหนดคดีและกฎเดียวกัน รวมกฎการปิดบังข้อมูล ข้อมูลผู้เล่นที่ส่งออกต้องจำกัดตามการค้นพบ อย่าส่งข้อสรุปที่ engine คำนวณแล้วให้ neural-only ใช้เป็นคำตอบ
- **ขอบเขตที่ต้องตรวจให้ครบ:** การแทนเฉพาะ `engine.decide` ยังไม่เพียงพอหากการแสดงวัตถุ การเลือกบท การมอบหลักฐาน สมุดคดี หรือฉากจบยังเรียก symbolic เพื่อตัดสินความหมาย ห้ามเรียกรุ่นที่ยังพึ่งกฎเหล่านั้นว่าไม่มี symbolic

เริ่มประเมินแบบแยกชั้นโดยป้อนสถานะเริ่มและคำสั่งที่ตีความแล้วเหมือนกัน เพื่อทดสอบตัวตัดสิน นี่เป็นการทดลองควบคุมเฉพาะส่วนตัดสิน ยังไม่ใช่เกม neural-only เต็มระบบ จากนั้นทดสอบข้อความผู้เล่นจริงผ่านระบบทั้งชุดเพื่อรวมความผิดพลาดด้านภาษา รายงานสองผลแยกกัน

แยกการประเมินทีละคำสั่งบนสถานะที่กำหนดถูกต้อง ออกจากการเล่นหลายตาที่ระบบใช้สถานะจากผลของตัวเอง แบบหลังจึงเห็นการสะสมของข้อผิดพลาด ห้ามนำความถูกต้องของแบบแรกไปอ้างว่าระบบติดตามสถานะได้ตลอดเกม

ใช้โมเดลรุ่นเดียวกันสำหรับส่วนที่เทียบ กำหนดงบเรียกโมเดล ข้อมูลเข้า และการตั้งค่าที่ทำซ้ำได้ บันทึกเวลาและค่าใช้จ่ายจริง หากโครงสร้างทำให้จำนวนครั้งเรียกต่างกันให้รายงาน ไม่ซ่อนเป็นผลของเนื้อเรื่องอย่างเดียว

เส้นทางคำสั่งตรงที่ข้ามการตีความภาษาต้องใช้นโยบายเดียวกันหรือรายงานแยก บันทึก retry/timeout และแยกความล้มเหลวของบริการออกจากความผิดเชิงตรรกะ การทดสอบการตัดสินใช้นาฬิกาที่ควบคุมได้ ส่วนการเล่นจริงบันทึกเวลารอระบบด้วย เพื่อแยกผลที่เกิดจากเวลาสืบสวนเหลือน้อยลง

## 6. ชุดสถานการณ์และตัวชี้วัด

ความซับซ้อนในชุดทดสอบต้องระบุแยกอย่างน้อยสามแกน: จำนวนขั้นที่ต้องเชื่อมข้อสรุป, จำนวนเงื่อนไขที่ต้องพิจารณาพร้อมกัน/มีทางเลือก, และจำนวนช่วงการค้นพบที่ต้องรักษาความรู้ให้ตรงสถานะ ไม่รวมทุกอย่างเป็นเพียงจำนวนเอกสาร

สร้างกรณีคู่ใกล้กัน เช่น มี/ไม่มีพยานช่วงเหตุ มีสองสายเชื่อมบุคคล/มีสายเดียว พบหลักฐานแล้ว/เพียงพิมพ์อ้างชื่อ และมีต้นทางอิสระ/ฟังต่อจากคนเดิม ทุกคู่เปลี่ยนเฉพาะข้อมูลที่เกี่ยวข้องและต้องยังเป็นสถานะที่เกิดได้ตามเรื่อง

มีทั้งกรณีง่าย ยาก คำสั่งที่ควรผ่าน และคำสั่งที่ควรปฏิเสธ ตรึงชุดทดสอบที่ไม่ใช้ปรับ prompt และตรวจคำตอบอ้างอิงจาก A2/ข้อกำหนด B ก่อนรัน การอนุมานจากกฎที่เขียนผิดไม่กลายเป็นคำตอบถูกเพียงเพราะตรง engine

|---|---|
| ความถูกต้องของระบบ | ยอมรับ/ปฏิเสธถูกต้องแยกกัน เลือกบทและหลักฐานตรงสถานะ ตัดสินฉากจบตรงเงื่อนไข |
| การรักษาขอบเขตข้อมูล | ไม่ใช้หลักฐานที่ยังไม่พบ ไม่เฉลยบทที่ยังไม่เปิด ไม่สร้างข้อเท็จจริงหรือเหตุผลที่ไม่รองรับ |
| ความสม่ำเสมอ | ผลของกรณีเทียบเท่าและการรันซ้ำ รวมความผิดพลาดที่สะสมระหว่างหลายตา |
| ความเข้าใจผู้เล่น | อธิบายเหตุที่พยานตอนไฟดับไม่ตัดโอกาสก่อนหน้านั้น แยกความผิดวินเซนต์ และเชื่อม C กับแรงจูงใจคืนนี้ |
| ประสบการณ์ผู้เล่น | จุดติดขัด การย้อนอ่าน การใช้คำใบ้ ความสับสน และความรู้สึกว่าการไขคดีมีเหตุผล; เวลาเล่นแยกจากเวลารอระบบ |

วัดความเข้าใจสั้น ๆ หลังยื่นคดีแต่ก่อนเฉลยละเอียด เพื่อไม่ให้วัดเพียงการจำฉากจบ ใช้คำถามปลายเปิดไม่ชี้คำตอบและเกณฑ์ให้คะแนนที่กำหนดก่อน หากคำถามระหว่างเล่นถูกใช้ช่วยสอน ต้องให้เหมือนกันทั้งสองรุ่นและนับเป็นส่วนหนึ่งของประสบการณ์ ไม่ถือว่าเป็นเครื่องวัดที่ไม่มีผลต่อผู้เล่น

ผู้เล่นที่รู้เฉลยแล้วไม่ควรเป็นกลุ่มเปรียบเทียบครั้งแรกของคดีเดียวกันอีกฝั่งโดยไม่มีการควบคุมผลจากการเรียนรู้ การกำหนดจำนวนผู้เล่นและสถิติเป็นงานออกแบบการทดลองหลังได้ข้อมูลนำร่อง ไม่กำหนดจากจำนวนหลักฐานในเรื่อง

## 7. เกณฑ์ส่งมอบระยะ B ที่ปรับแล้ว

1. แผนผังหลักฐานและข้อสรุป ระบุแหล่งข่าว เงื่อนไข ความไม่แน่ชัด และความหมายที่เปลี่ยนเมื่อได้ข้อมูลเพิ่ม
2. บทและการ์ดสถานการณ์ที่จับคู่ **สิ่งที่ผู้เล่นเข้าใจเพิ่ม / สิ่งที่ระบบต้องตัดสิน** ครอบคลุมหกสถานการณ์ในหัวข้อ 2
3. เส้นทางจบทั้งสามคู่ พร้อมนับจำนวนหลักฐานและตรวจว่าไม่ต้องเก็บของทุกชิ้นเพื่อชนะ
4. ชุดตัวอย่างคำสั่งและสถานะที่มีคำตอบอ้างอิง รวมข้อมูลไม่พอ ข้อมูลขัดข้อกล่าวหา และการอ้างสิ่งที่ยังไม่พบ
5. แผนลองเล่นเพื่อตรวจความเข้าใจระหว่างการสืบสวนและก่อนเฉลย พร้อมกำหนดขอบเขต baseline ให้ชัดก่อนลงโค้ด

การเพิ่มด่านล็อกยังทำหลังทดสอบแกนคดี แต่หากจะใช้ด่านเพื่อทดสอบลำดับการกระทำ ต้องระบุหน้าที่ในการทดลองและในการเล่าเรื่องตั้งแต่ B

## 8. แหล่งอ้างอิงและขอบเขตของข้อเสนอ

[เอกสาร TextWorld](https://textworld.readthedocs.io/en/1.5.3/notes/framework.html) ยกตัวอย่างสภาพแวดล้อมเกมข้อความที่แยกพารามิเตอร์จำนวนวัตถุ ความยาวภารกิจ ความซับซ้อน และความละเอียดข้อความได้ ใช้เป็นแนวคิดประกอบการแยกมิติความยาก ไม่ใช่ผลทดลองที่ยืนยันว่า NeSy จะเหนือกว่า neural-only ในเกมนี้

รายละเอียดการเทียบและเกณฑ์ข้างต้นเป็นข้อเสนอสำหรับโครงการนี้ ต้องตรวจความเป็นไปได้ใน B และตรึงก่อนทดลองจริง
